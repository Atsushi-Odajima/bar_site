# 炉端と酒「灯」— 居酒屋ホームページの制作見本

> **このサイトは架空店舗の制作見本です。** 店名・住所・電話番号・メニュー・予約はすべて架空で、
> 実際の予約・送信・通知は行われません。

ミツモア・くらしのマーケットで「ホームページ作成」をご検討中の飲食店オーナー向けに、
炉端焼きと地酒の居酒屋を想定して作った見本サイトです。スマホでの見やすさと、Web 予約〜店舗側の予約管理までを体験できることを重視しています。

| 画面 | パス | 内容 |
|---|---|---|
| トップ | `/` | 店の紹介・今日のおすすめ・お品書き・お酒・お席・コース・よくある質問・アクセス |
| 予約体験 | `/reserve/` | 人数・日付・時間・席 → お客様情報 → 内容確認 → デモ完了 |
| 店舗側予約管理画面（操作見本） | `/admin/` | 日付別の予約一覧・ステータス変更・詳細・デモデータの初期化 |

スクリーンショット：`docs/screenshots/`　／　紹介文・特徴説明：`docs/promo.md`

## デモ用パスワード

- 管理画面（`/admin/`）のパスワード：**`demo`**（画面にも表示しています）
- これは**体験用の入口**です。本番の認証や情報保護の仕組みではありません（パスワードはページのプログラム内に含まれており、誰でも確認できます）。

## 起動方法

Node.js 20 以上（動作確認は Node 22）。

```bash
npm install
npm run dev        # 開発サーバー http://localhost:5173
npm run build      # 型チェック＋本番ビルド（出力：dist/）
npm run preview    # ビルド結果の確認 http://localhost:4173
```

その他：`npm run icons`（`src/icons/*.svg` を変換）、`npm run credits`（`src/data/photos.json` から `CREDITS.md` を生成）

## デプロイ（Vercel）

`vercel.json` に設定済みのため、Vercel でこのリポジトリを読み込むだけで公開できます。

1. Vercel のダッシュボードで「Add New… → Project」から `Atsushi-Odajima/bar_site` を選ぶ（Import）
2. 設定は自動で入ります（Framework：Vite、Build Command：`npm run build`、Output Directory：`dist`）。そのまま「Deploy」
3. 以降は、GitHub の `main` に取り込む（マージする）たびに本番が更新され、PR ごとにプレビューURLが発行されます

- 公開URLは Vercel の本番URL（`VERCEL_PROJECT_PRODUCTION_URL`）がビルド時に自動で使われ、OGP 画像の絶対URLになります。独自ドメインを使う場合は環境変数 `SITE_URL` に設定してください。
- 制作見本として公開する場合、環境変数 `SITE_MODE` は**設定しない**でください（既定の demo のまま＝検索結果に出ない・連絡先はデモ案内）。
- `/reserve/`・`/admin/` は直接開いても表示されます（`/admin` のように末尾のスラッシュがない場合は自動で `/admin/` に移動します）。

## デモ（制作見本）と本番の切り替え

`src/config/site.ts` の `mode`（または環境変数 `SITE_MODE`）で動作が変わります。

| 項目 | demo（既定） | production |
|---|---|---|
| 電話・LINE・SNS ボタン | 押すと「実店舗ではここから〜」の説明ダイアログ | `tel:`・実際のURLへ移動 |
| アクセスの地図 | 仮の案内図（「地図が入る見本」と表示） | Google マップ埋め込み |
| 検索エンジン | `<meta name="robots" content="noindex">` | インデックス可、canonical 出力 |
| 構造化データ（`Restaurant` JSON-LD） | **出力しない**（架空の住所・電話を渡さないため） | 店舗情報から出力 |
| 「架空店舗の制作見本」表示・見本の案内 | 表示 | 非表示 |

`robots.txt` は全体をブロックしていません（ブロックすると検索エンジンが `noindex` を読めないため）。

### 本番導入時に設定する項目

- `src/config/site.ts`：店名・住所・電話・営業時間・定休日・席数・`links`（tel / LINE / Instagram / X / 食べログ / 地図の埋め込みURL）・`siteUrl`
- `src/data/content.ts`：メニュー・価格・おすすめ・コース・よくある質問・文章
- `src/styles/tokens.css`：配色・書体・余白（別の店舗・業態への展開はここと上の2ファイルが中心）
- 写真：`public/images/` に WebP（長辺 800 / 1600px）を置き、`src/data/photos.json` を更新 → `npm run credits`
- OGP 画像：`scripts/og-image.html` を編集してブラウザで 1200×630 に撮影し `public/og.jpg` を差し替え
- 構造化データ：`src/templates/layout.ts` の `restaurantJsonLd()`（料理ジャンル・営業時間などを実際の値に）

## 予約データの保存先と、本番化に必要なこと

予約の保存処理は **`src/lib/reservation-store.ts` の1ファイルに集約**しています。
現在はブラウザの `localStorage` に保存するデモ実装で、ファイル末尾の `export const store = ...` が差し替え箇所です（Supabase 実装の手順をコメントで記載）。

ただし、**保存先を変更するだけでは本番運用できません。** 本番化には少なくとも次の開発・設定が必要です。

- **管理画面の認証と権限**：店舗スタッフだけがログインできる仕組み（例：Supabase Auth）と、データベース側の行レベルの権限設定（RLS）
- **予約通知**：お店への新着通知、お客様への受付確認メール（またはLINE）
- **空席・在庫の管理**：実際の席数・卓数に基づく空き計算（現在の「満席」「残りわずか」は日付と時刻から計算した**デモ用の固定データ**です）
- **二重予約の防止**：同じ席・時間の同時予約をサーバー側で防ぐ処理（現在の重複防止は「同じ操作の二重クリック」のみ）
- **入力内容の検証**：ブラウザ側に加えてサーバー側でも検証
- **個人情報の扱い**：プライバシーポリシーの掲載、保存期間、通信の暗号化（HTTPS）
- 必要に応じて：キャンセル・変更の受付、営業日カレンダー（臨時休業・祝日）、コース選択、7名以上の団体予約

## この見本で使っている仕組み

- **Vite + TypeScript（フレームワークなし）**：3画面だけの静的サイトのため。ページの HTML はビルド時に `src/templates/*.ts` が設定ファイルから生成し、実行時の JavaScript は操作部分だけにして表示を軽くしています。
- **演出**：暖簾のオープニング（初回のみ・約1.3秒・スキップ可・操作をブロックしない）、和紙のお品書き（本文は常に読める状態で紙の余白と軸だけが動く）、提灯の点灯、黒板の装飾線、ヒーローの火の粉（少数・画面外で停止）、PC のみ写真のパララックス。
  GSAP + ScrollTrigger はお品書きとパララックスだけに使い、読み込み完了後に遅延読み込みしています。Lenis は使っていません（通常のスクロール）。
- `prefers-reduced-motion` が有効な端末では演出を止め、完成状態を表示します。JavaScript が動かなくても本文・価格・ボタンは表示されます。
- 動作確認用：`/reserve/?demo-fail` で開くと「保存に失敗した場合」の表示を再現できます。

## 確認結果（2026-10-22 時点）

### Lighthouse（実測）

- 条件：Lighthouse 12.8.2、モバイル設定（既定のエミュレーション：低速4G相当・CPU 4倍減速）、Chromium、
  ローカルの `vite preview`（gzip 配信）で計測。Google Fonts は外部から取得。Cloudflare Pages 上では未測定。
- トップは3回計測し、Performance は 85〜89 の範囲で変動しました。

| ページ | Performance | Accessibility | Best Practices | SEO |
|---|---|---|---|---|
| `/` | 85〜89 | 100 | 100 | 66 ※ |
| `/reserve/` | 100 | 100 | 100 | 63 ※ |
| `/admin/` | 100 | 100 | 100 | 63 ※ |

※ SEO の減点は、公開デモに意図的に付けている `noindex` によるものです。

### 動作確認（Playwright で自動操作）

- 375 / 390 / 768 / 1440px で横方向のはみ出しなし（3画面）
- 文字サイズ 200% でも横はみ出しなし、下部の電話・予約・LINE・地図ボタンを操作可能
- キーボード：お品書きのタブ（←→ / Home / End）、予約フォーム、ダイアログ（Esc で閉じると元のボタンにフォーカスが戻る）、スキップリンク
- 予約：定休日・過去日・経過済み時刻は選択不可、7名以上は団体相談の案内、人数変更で無効になった席を解除、
  ブラウザの戻る／進む・再読み込みで入力を保持、二重クリックでも1件のみ登録、保存失敗時は完了と表示せず再試行を案内
- 予約完了 → 管理画面で該当予約を強調表示 → ステータス変更 → 詳細表示 → デモデータ初期化まで通して動作
- 端末の実機（iPhone / Android）での確認、スクリーンリーダーでの読み上げ確認は未実施です
